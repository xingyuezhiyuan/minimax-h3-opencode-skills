# 多镜头工作流

## 触发条件

以下任一条件满足时进入多镜头判断：

- 用户明确要求多镜头、分镜、切镜、蒙太奇或逐镜规划；
- 用户给出的时长达到10秒，但没有说明采用单镜头还是多镜头。

第一种情况直接进入规划器；第二种情况先让用户选择是否启用多镜头。

## 五阶段状态机

### 阶段1：确定镜头数量

规划器首先询问镜头数量。非二选一问题至少提供5个实际可用的选项，例如2、3、4、5、6镜头。

### 阶段2：确定全局节奏

根据缺失信息询问总时长分配、整体节奏、镜头连续性和转场倾向。这一阶段只决定跨镜头规则，不替代逐镜规划。

### 阶段3：逐镜询问

从 `Shot 1` 开始，每次只规划当前镜头。每个镜头覆盖：

1. 镜头内容与叙事功能；
2. 景别与构图；
3. 运镜类型、目标、速度和幅度；
4. 人物动作、表演与表情变化；
5. 开场方式或与上一镜头的转场；
6. 环境声、拟音、对白和音乐重点。

每个非二选一问题至少提供5个有实质差异的选项。当前镜头完成后，AI先给出中文摘要，再询问是否确认。只有确认后才能进入下一镜头。

### 阶段4：连续性检查

所有镜头完成后，检查人物身份、服装、道具、空间方向、光线、动作接续、声音桥和时间分配是否连续。

### 阶段5：整体确认

向用户展示完整镜头表并请求最终确认。确认后输出：

```text
multishot_plan_status: confirmed
```

该状态是进入最终 H3 提示词格式化的唯一放行条件。

## 问题数量

OpenCode 的 `question` 工具没有“三个问题”的工作流上限。规划器为每个镜头设置6个核心问题，是为了覆盖完整镜头设计，不能因为通用提问习惯而缩减为3个。
