# 路由规则

## 决策顺序

总导演按以下顺序判断，不允许下游 Skill 绕过该顺序自行改模式。

1. 判断用户是在创建提示词还是审查已有提示词。
2. 检查是否明确要求多镜头，以及时长是否达到10秒。
3. 检查是否存在图片、视频或音频参考素材。
4. 判断图片是纯边界帧，还是承担人物、物品、场景、风格等参考责任。
5. 把确认后的创意简报或镜头计划交给唯一一个最终格式化 Skill。

## 路由矩阵

| 用户条件 | 路由结果 |
| --- | --- |
| 只有文字创意、脚本或故事板 | `minimax-h3-text-video-prompt` |
| 存在人物、角色、物品、场景、风格、动作、镜头或音色参考 | `minimax-h3-reference-video-prompt` |
| 普通上传图片但用户没有明确声明其仅为首帧或尾帧 | `minimax-h3-reference-video-prompt` |
| 明确声明图片仅为首帧、尾帧或首尾帧，且不承担参考一致性责任 | `minimax-h3-keyframe-video-prompt` |
| 已有 H3 提示词需要检查、纠错或重写 | `minimax-h3-prompt-reviewer` |
| 明确提出多镜头、分镜、切镜、蒙太奇或逐镜设计 | 先进入 `minimax-h3-multishot-planner` |
| 时长达到10秒且未说明单镜头或多镜头 | 先询问是否启用多镜头 |

## 图片路由原则

“首帧”是图片在时间轴上的位置，“参考图”是图片承担的控制责任，两者可以同时成立。只要图片还用于保持人物身份、服装、物品、场景或风格一致性，就应采用参考一致性模式，并在提示词中描述首帧语义，而不是切换到纯关键帧模式。

## 审查请求

用户提供已有提示词时，总导演仍然先读取官方规范，然后把提示词和已知素材交给 Reviewer。Reviewer 可以修复字段结构、时间线、运镜、对白、声音、参考标签和互相矛盾的约束。
